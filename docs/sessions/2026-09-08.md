## What happened

**The wake word had nothing to listen with, and the reason was upstream.**
Hands free armed and reported no bundled model. The operator guessed
openWakeWord downloads models on first use. It is worse than that: the wheel
contains **no models at all** — not the six published phrases, and not the two
feature models every phrase runs on top of. There is no `resources/models`
directory after a clean install. Verified by installing the wheel here and
looking.

Two further traps, both of which would have made a correct download still look
like a failure:

- **A published name is not a file name.** `hey_jarvis` is released as
  `hey_jarvis_v0.1.onnx`. The old `_bundled()` looked for an exact match and
  would have produced the identical error message after a successful download.
- **A failed download still writes a file.** openWakeWord's downloader streams
  the response body whatever the status code was, so a proxy error page lands
  on disk under the model's name and the download reports success.

`ranger wake install` and `ranger wake show` (`d8123be`). The command says the
source out loud before fetching — the openWakeWord project's own GitHub release
assets, `dscripka/openWakeWord`, not a mirror or a model hub — because a wake
word is a network fetch of a binary that then listens to a room. It verifies
sizes afterwards rather than trusting the download. `ranger doctor` now reports
a missing model as a **problem** whenever `wake.enabled` is true, at the point
hands free is switched on rather than on the first arm. Not installing the
extra at all stays a todo.

Models install inside the openWakeWord package, not next to the vault. Not a
choice: its preprocessor finds the two feature models by a hardcoded path.
Rebuilding the venv loses them.

Verified end to end here for the first time: download, resolve, load, and score
real frames through the real model.

**`scripts/train_wake_word.py` was fiction** and would have failed at import.
It called `generate_samples` from `openwakeword.utils`, which does not exist,
and `train_model` as a function when it is a method on a class. Written from
memory and never run.

Replaced (`3530f05`) with something that writes a **Colab notebook**, derived
from openWakeWord's own `automatic_model_training.ipynb` fetched and read
rather than remembered. Three changes, all in one cell: the phrase, thirteen
adversarial negatives written for it, and sample counts raised to openWakeWord's
own recommended minimum, which its example notebook sits below because it is
demonstrating the mechanism. The config is read from openWakeWord's
`examples/custom_model.yml` **inside the clone** and then overridden, so it
cannot drift from whatever version was cloned — a config written from scratch
drifts silently, as a key that is quietly never read.

`docs/training-hey-ranger.md` is the walkthrough, including the two questions
that were asked plainly and answered plainly: what a badly trained model looks
like against a phrase that was never going to work, and what the free Colab
tier realistically gives.

**The acceptance test, and two bugs in it found while the run was live**
(`a71ef64`). The last cell scores the trained model and prints detections
against false fires per hour at seven thresholds. That table is what decides
whether the model is usable and what `wake.threshold` should be. Two things
were wrong, both of which would only have surfaced at the end of a three hour
run:

- The trainer nests its output. Clips go to
  `output_dir/model_name/positive_test`; the exported model goes to
  `output_dir/model_name.onnx`. Not the same level. The cell read positives
  from the model's level and would have found none.
- It counted false fires against the background audio from step 4, which is
  the audio mixed into the training negatives. The model has already been
  trained not to fire on those exact clips, so the number would have been
  flattering by an unknown amount — worse than no number. There is now a step
  that continues the same music stream past where step 4 stopped.

**The alias map had no tests, and writing them found a bug that hid itself**
(`6eebe51`). 298 lines of name matching, wired into account resolution, the
quiet scan, recall and `ranger doctor`, with nothing exercising any of it.

`parse()` stripped each line before looking for a list item, so the indented
example in the file's **own header** parsed as a real alias. Every `aliases.md`
Ranger wrote carried a phantom `BWI Company -> BWI Companies` — which is one of
the six genuine pairs, so the file looked right. The visible symptom was that
`ranger alias remove BWI Company` reported success and changed nothing, because
re-rendering put the header back with the alias inside it. A pair is now a list
item at column zero, which is markdown's own rule that indented text is a code
block.

42 tests, organised around the rule the module exists under: Ranger proposes and
the operator approves. So the ones that matter most are what is *not* suggested
(Pegasus Logistics against Pegasus Packaging) and what is *not* silently dropped
(an alias whose canonical account stopped existing).

## Designed, not built

**Window surfacing and the spoken dismissal.** Answered rather than built,
because the operator asked first.

Bringing the window forward on a fire is the same Windows problem as the
shortcut and worse: speech is not an input event, so the process has less claim
to foreground than it did when the operator double-clicked something. But
**restoring and foregrounding are two different permissions**, which had been
conflated. `ShowWindow(SW_RESTORE)` is expected to work; `SetForegroundWindow`
is expected to be refused, and Windows flashes the taskbar button instead. So
the realistic outcome is that the window un-minimises and appears, probably
without focus, plus a flashing taskbar button. The mechanisms that genuinely
surface it — a `HWND_TOPMOST` toggle, or `AttachThreadInput` — both have costs
(over a screen share; a deadlock on a hung foreground thread) and go behind
config rather than being the default.

`focus_window()` currently ignores `SetForegroundWindow`'s return value and
reports success unconditionally, which is why nobody knows what that machine
does. Logging the real answer is how it gets settled.

"That's all Jarvis" is a rule on a completed transcript, not a second model.
The rule is that **the dismissal is the whole utterance, not a substring**, so
"tell Rusty that's all we need from Jarvis" runs as a turn and leaves the
window alone. Detected before the turn runs, so it costs no tokens and never
enters the history. Derived from `wake.phrase`, so training "hey ranger"
changes the dismissal without a second edit.

**Conversation mode**, agreed as designed:

- **Two timers, not one.** Eight seconds to *start* speaking; once speaking, the
  existing utterance rules take over. Fifteen was seven extra seconds of open
  mic for a case that rarely arrives.
- **Anchored to end of playback, not end of turn**, or the window burns down
  while Ranger is still talking. The condition is *both* "turn complete"
  (Python knows) and "speaker queue empty" (the browser knows) — the queue
  drains mid-reply whenever the model is slower than the speaker, so a naive
  `onDone` would open the window three times per answer.
- **Cap at 3** for the first week, 5 thereafter. Then the phrase is needed
  again.
- **Closed by**: the dismissal, a gated action (hard close — an open mic while
  a confirmation card is up mixes capture with a safety decision), typing or
  clicking, the socket dropping, the mic check failing. Not barge-in, which
  should continue the conversation.
- **False fire cost**: up to 6× in captured audio and turns, not unbounded. The
  common false fire — no speech after it — does not change at all, because no
  reply means no window. Only the fires that already caught speech amplify.
- **Mic check runs on window open** as well as on the poll, so a call that
  started four seconds ago is caught at open rather than up to five seconds
  later. Failure closes the window *and* disarms.
- **A draining ring, not a third colour.** Orange keeps one meaning — the
  microphone is live — and the ring says "and it stops by itself". Three
  colours means learning three colours.
- Every open and close in the audit log with a reason (`timer`, `dismissed`,
  `gated`, `typed`, `mic_check`, `disarmed`, `cap`). "How often it stayed open
  when I had already walked away" is closes with reason `timer` and no speech.
